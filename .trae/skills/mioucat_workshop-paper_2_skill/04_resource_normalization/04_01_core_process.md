# 核心流程和基本结构

## 概述

本模块详细介绍了 Paper2Skill 工具对各种资源进行规范化处理的核心流程和基本结构要求。通过遵循本模块的指导，您可以确保不同类型资源的处理流程标准化、系统化。

## 标准操作流程 (SOP)

**重要**：在进行任何资源规范化处理前，请严格按照以下流程执行：

### PDF 文档规范化处理流程

1. **确定处理文件**：明确要处理的PDF文件，确认其在 `pdf/output/` 目录下的位置
2. **阅读原始MD文档**：阅读经过 `process_pdf.py` 脚本处理后生成的原始MD文档
3. **识别文档信息**：
   - 确认文章的独有标识符（如DOI或其他唯一标识）
   - 确认文章的发表期刊
   - 确认期刊的出版商（主公司）
4. **创建目录结构**：
   - 在 `llm_processed/` 目录下创建 `出版商/期刊/文章独有标识/` 三级目录结构
   - 在文章独有标识目录下创建 `chapters/`（章节）和 `images/`（图片）子目录
   - 创建空的 `{文章独有标识}.md` 入口文档
5. **查找处理指南**：查找针对该期刊的PDF处理指南（PDF guide）
6. **章节拆分确认**：
   - **核心原则**：能够拆就一定要拆（只要文档中存在的章节，就必须提取）
   - 对照PDF guide中的章节划分建议
   - 在原始MD文档中查找完全匹配的章节标题
   - 基于朴素认知识别其他需要划分的章节标题
   - 综合两者确定最终的章节划分
7. **章节拆分**：按照确定的章节划分，将内容拆分为多个章节文件，保存到 `chapters/` 目录
8. **图片处理**：
   - 找到 `pdf/output/` 目录下该文章的图片文件夹
   - 将图片复制到 `llm_processed/` 目录下的 `images/` 子目录
   - 对照原始MD文档，确认每张图片在文章中对应的Figure编号
   - 按照文章中的Figure编号重命名图片文件
9. **图片检查**：
   - 运行 `scripts/check_image_sizes.py` 脚本检查图片尺寸
   - 识别可能是版权说明或期刊标签的图片
   - 在对话窗口中记录这些可能的版权相关图片，提示用户
10. **完善入口文档**：
    - 参考PDF guide的要求，编写入口文档
    - 添加章节导航和图片引用
11. **用户确认**：
    - 提示用户确认章节文件是否合理生成
    - 提示用户确认图片标注是否正确
    - 提醒用户如果有不正确的地方，一起查找原因
    - 建议用户更新PDF guide以反映新发现的处理规则
12. **最终处理**：
    - 用户确认标准化完成后，删除多余的图片文件
    - 确认标准化过程已完成

### HTML 和 GitHub 文档处理流程

1. **确定处理文件**：明确要处理的HTML或GitHub文档
2. **识别资源类型**：确定资源类型（HTML或GitHub）
3. **识别唯一标识符**：确定资源的唯一标识符（如URL或项目名称）
4. **创建目录结构**：在 `llm_processed/` 目录下创建相应的目录结构
5. **建立内层目录**：创建 `chapters/` 和 `images/` 子目录
6. **创建空入口文档**：创建空的入口文档
7. **确认原始文档结构**：阅读原始文档，识别结构
8. **章节拆分**：将内容拆分为多个章节文件
9. **处理图片文件**：处理并组织图片文件
10. **完善入口文档**：更新入口文档，添加导航和引用
11. **用户确认**：与用户确认处理结果
12. **更新处理规则**：将新发现的处理经验更新到处理规则文档

## 资源分类与组织

### 资源类型识别

- **PDF文档**：学术期刊、会议论文、预印本、专利文献、技术报告、书籍章节
- **HTML文档**：学术网站、科技博客、在线教程、新闻文章
- **GitHub项目**：开源软件、数据集、技术文档

### 来源识别与分类

- **PDF文档**：识别出版社、会议组织、预印本平台等
- **HTML文档**：识别网站域名、组织名称等
- **GitHub项目**：识别用户名/组织名、项目名等

### 目录结构

所有资源类型均采用三级目录结构，各层级对应关系如下：

| 资源类型 | 一级目录（对应出版社） | 二级目录（对应期刊） | 三级目录（对应文章独有标识） |
|----------|----------------------|----------------------|------------------------------|
| PDF 文档 | 出版社名称（如 Elsevier） | 期刊名称（如 Cell） | 文章 DOI 后缀 |
| HTML 文档 | 网站来源（如 Wechat） | 公众号/栏目名称 | 文章 URL 或标题标准化形式 |
| GitHub 项目 | 代码托管平台（如 GitHub） | 用户名/组织名 | 仓库名称 |

### 层级对齐说明

- **一级目录**：代表资源的主要来源，对应 PDF 文档的出版社层级
- **二级目录**：代表资源的具体分类，对应 PDF 文档的期刊层级
- **三级目录**：代表资源的唯一标识，对应 PDF 文档的文章独有标识层级

这种层级对齐确保了不同资源类型的目录结构保持一致的组织逻辑，便于统一管理和后续处理。

### 常见资源类型与来源映射

| 资源类型 | 来源示例 | 目录路径示例 |
|----------|----------|-------------|
| pdf | Elsevier | `llm_processed/Elsevier/Cell/` |
| pdf | Springer Nature | `llm_processed/Springer_Nature/Nature/` |
| html | Wechat | `llm_processed/Wechat/科研圈/文章URL标识/` |
| github | GitHub | `llm_processed/GitHub/MiouCat/Paper2Skill/` |

## 章节目录结构

### PDF文档结构

```
资源标识/
├── {资源标识}.md     # 入口文档
├── chapters/      # 章节目录
│   ├── abstract.md            # 摘要部分
│   ├── introduction.md        # 引言部分
│   ├── methods.md             # 方法部分
│   ├── results.md             # 结果部分
│   ├── discussion.md          # 讨论部分
│   ├── references.md          # 参考文献
│   └── supplementary_information.md  # 补充信息
└── images/        # 图片目录
    ├── figure_1.jpeg
    ├── figure_2.jpeg
    └── ...
```

### HTML文档结构

```
资源标识/
├── {资源标识}.md     # 入口文档
├── chapters/      # 章节目录
│   ├── introduction.md        # 介绍部分
│   ├── content.md             # 内容部分
│   ├── references.md          # 参考文献/链接
└── images/        # 图片目录
    ├── image_1.jpeg
    ├── image_2.jpeg
    └── ...
```

### GitHub项目结构

```
资源标识/
├── {资源标识}.md     # 入口文档
├── chapters/      # 章节目录
│   ├── overview.md            # 项目概述
│   ├── installation.md        # 安装说明
│   ├── usage.md               # 使用指南
│   └── contributing.md        # 贡献指南
└── images/        # 图片目录
    ├── screenshot_1.jpeg
    ├── screenshot_2.jpeg
    └── ...
```
