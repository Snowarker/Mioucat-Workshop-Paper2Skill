# 技术报告识别指南

## 概述

本指南详细介绍如何从转换后的Markdown文档中识别技术报告和说明书，包括识别特征、方法和实践示例。通过分析文档中的特定标识和模式，我们可以准确判断一篇文档是否为技术报告或说明书。

## 识别特征

### 1. 标题和标注

**关键词**：
- "Protocol"
- "Guide"
- "Manual"
- "Report"
- "Technical Report"
- "User Guide"
- "Instruction"
- "Handbook"
- "Procedure"
- "Method"

**示例**：
- "Protocol for Limited Proteolysis Coupled to Mass Spectrometry"
- "User Manual for XYZ Software"
- "Technical Report: Climate Change Impact Assessment"

### 2. 内容结构

**技术报告通常具有以下结构**：
- 标题
- 版本信息
- 作者/编写者
- 日期
- 摘要/概述
- 目的/范围
- 材料/设备
- 步骤/流程
- 结果/讨论
- 结论
- 参考文献
- 附录

**说明书通常具有以下结构**：
- 标题
- 版本信息
- 适用范围
- 材料清单
- 实验步骤
- 操作流程
- 注意事项
- 故障排除

### 3. 语言风格

**技术报告的语言风格**：
- 客观、准确
- 详细、具体
- 结构化、条理清晰
- 包含专业术语
- 可能包含图表、表格

### 4. 格式特征

**常见格式特征**：
- 包含编号列表
- 包含步骤说明
- 可能包含流程图
- 可能包含安全警告
- 可能包含版本历史

## 识别方法

### 1. 搜索技术报告关键词

在文档中搜索以下关键词：
- 技术报告相关词汇（如Protocol, Guide, Manual, Report等）
- 步骤相关词汇（如Step, Procedure, Process等）
- 材料相关词汇（如Materials, Equipment, Reagents等）

### 2. 分析内容结构

- 检查是否包含实验步骤、材料清单等内容
- 分析文档结构是否符合技术报告的特征
- 检查是否包含版本信息、日期等元数据

### 3. 检查语言风格

- 分析语言是否客观、详细、结构化
- 检查是否包含专业术语
- 检查是否包含操作说明和步骤指导

### 4. 分析格式特征

- 检查是否包含编号列表和步骤说明
- 检查是否包含流程图或其他技术图表
- 检查是否包含安全警告或注意事项

## 特殊情况处理

### 1. 混合类型文档

**识别特征**：
- 同时包含技术报告和其他类型文档的特征
- 可能是技术报告与学术论文的混合

**处理方法**：
- 识别为混合类型文档
- 记录主要类型和次要类型

### 2. 简短技术说明

**识别特征**：
- 篇幅较短
- 内容较为简洁
- 可能只包含核心步骤

**处理方法**：
- 识别为技术说明
- 与完整技术报告区分

### 3. 标准化技术文档

**识别特征**：
- 可能遵循特定标准或规范
- 可能包含标准编号或引用
- 格式较为正式

**处理方法**：
- 识别为标准化技术文档
- 记录相关标准信息

## 自动化识别流程

为了实现自动化识别，建议按照以下流程处理：

1. **提取技术报告关键词**：从文档中提取技术报告相关关键词
2. **分析内容结构**：检查是否包含实验步骤、材料清单等内容
3. **检查语言风格**：分析语言是否客观、详细、结构化
4. **分析格式特征**：检查是否包含编号列表、步骤说明等
5. **验证结果**：交叉验证通过不同方法获得的结果

## 技术说明书的唯一标识方法

由于技术说明书通常没有DOI等标准标识符，需要采用自定义的标识方法来确保唯一性。以下是推荐的唯一标识方案：

### 1. 复合标识结构

```
[项目/组织标识]-[方法/主题标识]-[文档类型]-[版本号]
```

### 2. 标识组成部分

- **项目/组织标识**：基于文档来源的组织或项目名称
- **方法/主题标识**：基于文档的核心方法或主题
- **文档类型**：基于文档的具体类型（如Protocol、Guide、Manual等）
- **版本号**：基于文档的版本信息

### 3. 示例

#### 示例1：EUBOPEN项目技术说明书

**标识**：`EUBOPEN-LiP-MS-Protocol-v1.0`

**组成**：
- 项目标识：`EUBOPEN`（基于项目名称）
- 方法标识：`LiP-MS`（基于核心方法）
- 文档类型：`Protocol`（基于文档类型）
- 版本号：`v1.0`（基于版本信息）

#### 示例2：软件用户手册

**标识**：`ACME-DataAnalysis-UserManual-v2.1`

**组成**：
- 组织标识：`ACME`（基于公司名称）
- 主题标识：`DataAnalysis`（基于软件功能）
- 文档类型：`UserManual`（基于文档类型）
- 版本号：`v2.1`（基于版本信息）

### 4. 目录结构建议

在`llm_processed`目录中，技术说明书可以按照以下结构组织：

```
llm_processed/
└── [项目/组织]/
    └── Technical_Protocols/  # 或其他适当的分类
        └── [唯一标识]/
            ├── [唯一标识].md
            └── images/
```

#### 示例目录结构

```
llm_processed/
└── EUBOPEN/
    └── Technical_Protocols/
        └── EUBOPEN-LiP-MS-Protocol-v1.0/
            ├── EUBOPEN-LiP-MS-Protocol-v1.0.md
            └── images/
```

### 5. 优势

- **唯一性**：结合多个维度的信息，确保与其他文档区分
- **可扩展性**：版本号可以随着文档更新而递增
- **可读性**：标识清晰易懂，包含关键信息
- **一致性**：与学术文档的标识风格保持一致
- **可追溯性**：通过标识可以快速了解文档的来源和内容

## 总结

通过本指南介绍的方法，您可以从转换后的Markdown文档中准确识别技术报告和说明书，并为其创建唯一标识符。这些信息对于后续的分类、汇总和分析工作非常重要。

**关键要点**：
- 技术报告关键词是识别技术报告的重要线索
- 内容结构（如实验步骤、材料清单）是技术报告的核心特征
- 语言风格客观、详细、结构化
- 格式特征包含编号列表、步骤说明等
- 技术说明书需要采用复合标识结构确保唯一性

通过系统应用这些方法，您可以建立一个准确、可扩展的技术报告识别和标识系统，适用于各种类型的技术文档。
