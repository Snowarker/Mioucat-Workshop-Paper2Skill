# 核心流程与环境设置

## 概述

本文档作为 Paper2Skill 工具核心流程与环境设置的总领文档，介绍工具的基础操作流程和环境配置方法。通过本章节，您将了解如何设置工具环境、处理不同类型的文档（论文、网页、GitHub 仓库、R 包、Python 包）以及提取技能信息的完整流程。所有处理流程遵循[项目理念与工程化框架](../SKILL.md#项目理念与工程化框架)中"入库即构建知识网络、保留 ground truth"的原则。

## 核心流程

### 1. 使用指南
- **目的**：提供工具的基本使用方法和流程
- **内容**：工具使用步骤、常见操作、最佳实践
- **参考文档**：[使用指南](01_01_usage_guide.md)

### 2. 环境设置
- **目的**：配置工具运行所需的软件和依赖（仅用于PDF处理）
- **内容**：Python 环境配置、依赖安装、系统要求
- **参考文档**：[环境设置](01_02_environment_setup.md)

### 3. PDF 转换
- **目的**：将 PDF 格式的论文和专利转换为可编辑的文本格式
- **内容**：PDF 转文本工具使用、格式处理、质量检查
- **参考文档**：[PDF 转换](01_03_pdf_conversion.md)

### 4. LLM 处理
- **目的**：利用大语言模型深度分析和理解文档内容
- **内容**：模型选择、参数设置、处理流程
- **参考文档**：[LLM 处理](01_04_llm_processing.md)

### 5. 技能提取
- **目的**：从处理后的内容中提取结构化的技能知识
- **内容**：技能识别、分类、结构化提取
- **参考文档**：[技能提取](01_05_skill_extraction.md)

### 6. GitHub 处理
- **目的**：处理 GitHub 仓库源代码，为大模型分析准备内容
- **内容**：仓库克隆、文件分析、内容提取
- **参考文档**：[GitHub 处理](01_06_github_processing.md)

### 7. 文档规范化
- **目的**：对处理后的文档进行规范化处理（主要用于PDF转换后的文档）
- **内容**：结构调整、格式统一、内容优化、章节拆分、图片处理
- **参考文档**：[文档规范化](01_07_document_normalization.md)
- **详细规范**：[资源规范化处理](../04_resource_normalization/04_resource_normalization.md)

### 8. HTML 处理
- **目的**：处理本地保存的 HTML 网页文件，如微信公众号文章
- **内容**：HTML 文件解析、内容提取、格式转换
- **参考文档**：[HTML 处理](01_08_html_processing.md)

## 工作流程

### 标准处理流程

#### PDF 文档处理流程（论文/专利）
1. **环境准备**：安装 Python 3.10/3.11 和必要依赖（仅用于PDF处理）
2. **PDF 转换**：将 PDF 文件转换为初始 MD 文档和图片
3. **文档规范化**：对初始 MD 文档进行结构调整、章节拆分、图片处理
4. **LLM 分析**：使用大语言模型处理规范化后的文档
5. **技能提取**：从处理后的内容中提取结构化的技能知识
6. **文档生成**：生成最终的 skill 文档
7. **质量检查**：检查生成文档的质量和完整性

#### HTML 文件处理流程（网页内容）
1. **准备 HTML 文件**：在浏览器中打开网页，右键另存为完整 HTML 文件
2. **HTML 处理**：组织 HTML 文件到合适的目录结构
3. **LLM 分析**：使用大语言模型处理 HTML 文件内容
4. **技能提取**：从处理后的内容中提取结构化的技能知识
5. **文档生成**：生成最终的 skill 文档
6. **质量检查**：检查生成文档的质量和完整性

#### GitHub 仓库处理流程（源代码）
1. **准备仓库**：获取 GitHub 仓库源代码
2. **GitHub 处理**：分析仓库结构，提取关键信息
3. **LLM 分析**：使用大语言模型处理源代码内容
4. **技能提取**：从处理后的内容中提取结构化的技能知识
5. **文档生成**：生成最终的 skill 文档
6. **质量检查**：检查生成文档的质量和完整性

#### 代码包处理流程（R 包 / Python 包）
1. **来源识别**：按[文档来源识别](../03_document_identification/03_document_identification.md)确定包来源（CRAN/Bioconductor/PyPI/conda-forge）
2. **获取原始材料**：下载源码包或记录安装命令，保留包名+版本号作为 ground truth
3. **元数据提取**：提取 DESCRIPTION / pyproject.toml 元数据与依赖关系
4. **LLM 分析**：使用大语言模型处理包文档、源码与版本记录
5. **技能提取**：从处理后的内容中提取结构化的技能知识
6. **文档生成**：生成最终的 skill 文档，链接回包材料
7. **质量检查**：检查生成文档的质量和完整性

### 不同文档类型的处理流程对比

| 文档类型 | 处理流程 | 参考文档 | 特殊说明 |
|---------|---------|---------|----------|
| PDF 文档 | 环境准备 → PDF 转换 → 文档规范化 → LLM 处理 → 技能提取 → 文档生成 | [PDF 转换](01_03_pdf_conversion.md)、[文档规范化](01_07_document_normalization.md) | 需要Python环境和依赖 |

| GitHub 仓库 | GitHub 处理 → LLM 处理 → 技能提取 → 文档生成 | [GitHub 处理](01_06_github_processing.md) | 直接处理源代码 |
| R 包 | 来源识别 → 获取原始材料 → 元数据提取 → LLM 处理 → 技能提取 → 文档生成 | [R 包文档识别](../03_document_identification/03_04_r_package_identification.md) | 需记录包名+版本号 |
| Python 包 | 来源识别 → 获取原始材料 → 元数据提取 → LLM 处理 → 技能提取 → 文档生成 | [Python 包文档识别](../03_document_identification/03_05_python_package_identification.md) | 需记录包名+版本号 |

## 技术要求

- **操作系统**：Windows 10/11 (64位)
- **Python 版本**：3.10.x（推荐版本，如 3.10.11，仅用于PDF处理）
- **依赖项**：详见 `requirements.txt` 文件（仅用于PDF处理）
- **硬件要求**：建议至少 8GB RAM，推荐 16GB 或更高

## 最佳实践

1. **环境配置**：确保所有依赖项都已正确安装，避免运行时错误
2. **文档预处理**：在处理前检查文档质量，确保内容完整
3. **参数优化**：根据文档类型和大小调整 LLM 处理参数
4. **质量控制**：处理后检查生成文档的质量，确保技能提取完整
5. **持续学习**：关注工具更新和新功能，不断优化处理流程

## 故障排除

### 常见问题

| 问题类型 | 可能原因 | 解决方案 |
|---------|---------|---------|
| 依赖安装失败 | 网络问题或版本冲突 | 检查网络连接，使用指定版本的依赖 |
| PDF 转换质量差 | PDF 扫描质量或加密 | 使用高质量 PDF，尝试不同的转换工具 |
| LLM 处理超时 | 文档过大或模型限制 | 分割文档，调整模型参数 |
| 技能提取不完整 | 文档结构复杂或内容质量差 | 优化文档预处理，调整提取参数 |

### 关于质量控制检查的说明

**重复分析的逻辑**：
- 在工具开发和使用过程中，为了确保所有重要信息都被捕获，我们采用了多层级的质量控制检查
- 虽然不同文档中可能存在重复的检查项，这是有意为之的设计
- 我们的原则是：宁可多做检查，也不要因为遗漏检查而导致信息丢失
- 这种重复分析有助于确保处理流程的完整性和准确性

**详细的质量控制检查项**：请参考 [资源规范化处理](../04_resource_normalization/04_resource_normalization.md) 文档中的质量控制部分。
