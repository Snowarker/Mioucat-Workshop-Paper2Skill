# 资料管理

## 概述

本文档作为 Paper2Skill 工具资料管理的总领文档，介绍如何管理和组织处理后的文档和技能信息。通过本章节，您将了解资料管理的方法、最佳实践和目录结构，为您的文档管理提供全面指导。资料管理遵循[项目理念与工程化框架](../SKILL.md#项目理念与工程化框架)中"入库即构建知识网络、保留 ground truth、相对路径交叉引用"的原则，目录与索引结构即知识网络的物理载体。

## 目录结构

### 标准目录结构

```
├── .trae/                  # Trae 内置配置目录（AI harness 配置目录之一）
│   └── skills/             # 技能文档目录（可跨 harness 复用）
├── llm_processed/          # LLM 处理后的文档
│   ├── {出版社名称}/       # 出版社目录（具象化示例）
│   ├── {会议名称}/         # 会议目录（抽象化分类）
│   ├── {预印本平台}/       # 预印本平台目录（抽象化分类）
│   ├── {机构名称}/         # 机构目录（抽象化分类）
│   ├── {网站名称}/         # 网站目录（抽象化分类）
│   └── {代码包仓库}/       # 代码包仓库目录（CRAN/Bioconductor/PyPI/conda-forge）
├── paper_skills/           # 提取的技能文档
│   ├── by_topic/           # 按主题分类
│   ├── by_method/          # 按方法分类
│   └── by_journal/         # 按期刊分类
├── pdf/                    # PDF 原始文档
│   ├── input/              # 输入 PDF
│   └── output/             # 转换后的输出
├── llm_standard/           # LLM 处理标准
│   └── std_guide/          # 标准指南
│       └── pdf_guide/      # PDF 处理指南
└── scripts/                # 辅助脚本
```

### 目录结构说明

| 目录 | 用途 | 参考文档 |
|------|------|---------|
| .trae/skills/ | 存储技能文档和使用指南 | [资料管理指南](05_data_management.md) |
| llm_processed/ | 存储 LLM 处理后的文档 | [资源规范化处理](../04_resource_normalization/04_resource_normalization.md) |

| pdf/ | 存储 PDF 原始文档和转换结果 | [PDF 转换](../01_core_process/01_03_pdf_conversion.md) |
| llm_standard/ | 存储 LLM 处理标准 | [PDF 文档处理规则索引](../../../../llm_standard/std_guide/pdf_guide/index.md) |

### 三级目录结构说明

**重要**：`llm_processed/` 目录下的所有资源均采用三级目录结构，具体如下：

- **一级目录**：资源的主要来源（如出版社名称、会议名称、预印本平台等）
- **二级目录**：资源的具体分类（如期刊名称、会议子类别等）
- **三级目录**：资源的唯一标识符（如 DOI 后缀、文章标题标准化形式等）

**详细的三级目录结构规范**：请参考 [资源规范化处理](../04_resource_normalization/04_resource_normalization.md) 文档中的详细说明。

## 文件命名规范

### 通用命名规范

- **文件命名**：使用小写字母、下划线和连字符
- **日期格式**：使用 YYYY-MM-DD 格式
- **版本号**：使用 vX.Y.Z 格式
- **唯一标识**：使用 DOI、ISBN 或自定义标识符

### 特定文件命名

| 文件类型 | 命名规范 | 示例 |
|---------|---------|------|
| 技能文档 | {技能名称}-{来源}-{年份}.md | lip_ms-nature_protocols-2017.md |
| 处理后文档 | {唯一标识符}.md | 10.1016_j.cell.2025.01.001.md |
| 图片文件 | figure_{序号}.{扩展名} | figure_1.jpeg |
| 脚本文件 | {功能}_{版本}.py | pdf_convert_v1.0.py |

## 版本控制

### 版本控制策略

1. **文档版本**：为重要文档建立版本控制
2. **变更记录**：记录文档的主要变更
3. **备份策略**：定期备份重要资料
4. **权限管理**：控制对资料的访问权限

### 版本控制工具

- **Git**：用于代码和文档的版本控制
- **云存储**：用于备份和共享资料
- **文档管理系统**：用于管理大量文档

### 代码包版本管理

代码类材料（R 包、Python 包、GitHub 仓库）的版本信息是知识网络节点的关键属性，入库时需显式记录：

- **R 包**：包名+版本号（如 `dplyr_1.1.4`）、来源仓库（CRAN/Bioconductor/GitHub）
- **Python 包**：包名+版本号（如 `pandas-2.2.2`，遵循 PEP 440）、来源仓库（PyPI/conda-forge/GitHub）
- **环境锁定文件**：`renv.lock`、`requirements.txt`、`environment.yml`，锁定分析环境的完整依赖版本
- **识别与获取方案**：详见 [R 包文档识别](../03_document_identification/03_04_r_package_identification.md) 与 [Python 包文档识别](../03_document_identification/03_05_python_package_identification.md)

## 最佳实践

1. **一致性**：保持目录结构和命名规范的一致性
2. **模块化**：将文档和技能信息模块化存储
3. **索引化**：为文档和技能信息建立索引
4. **标准化**：使用标准化的处理流程和格式
5. **安全性**：确保资料的安全性和隐私性

## 常见问题及解决方案

| 问题类型 | 可能原因 | 解决方案 |
|---------|---------|---------|
| 目录混乱 | 缺乏统一的目录结构 | 建立标准化的目录结构 |
| 命名不一致 | 缺乏命名规范 | 制定并遵循命名规范 |
| 版本混乱 | 缺乏版本控制 | 建立版本控制机制 |
| 查找困难 | 缺乏索引和搜索机制 | 建立索引和搜索系统 |
| 数据丢失 | 缺乏备份策略 | 建立定期备份机制 |

## 总结

资料管理是 Paper2Skill 工具使用的重要环节，通过有效的资料管理，您可以更好地组织和利用处理后的文档和技能信息。本章节提供了全面的资料管理方法和指南，帮助您建立规范、高效的资料管理体系。

随着项目的不断发展和资料的不断积累，资料管理方法也需要持续更新和优化。通过不断改进管理策略和工具，您可以提高资料管理的效率和质量，为 Paper2Skill 工具的使用提供更好的支持。
