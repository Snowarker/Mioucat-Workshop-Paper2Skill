# 资料管理哲学

## 概述

Paper2Skill 工具采用系统化的资料管理方法，确保从文献中提取的技能知识能够被有效地组织、检索和利用。本指南介绍资料管理的核心原则和实践方法。

## 资料管理流程

1. **源文档处理**：将原始PDF、HTML等文档转换为Markdown格式
2. **LLM处理**：使用大语言模型处理转换后的文档，生成结构化内容
3. **技能提取**：从处理后的文档中提取技能知识
4. **分类归档**：按照多维度分类体系组织技能知识
5. **索引维护**：建立和更新索引文件，确保资料可追溯

## 目录结构

目录按用途分为五类，由主到次依次为：**配置目录、处理工具与模型、标准与项目文档、源材料、处理产物**。

### 配置目录

项目根目录下的点开头目录存放不同工具的配置，按归属分为三类：

- **内置目录（当前使用）**
  - **.trae/**：Trae IDE 的内置配置目录
    - **skills/**：面向用户的 Skill 文档（使用指南、项目理念、版本更新记录）
    - **rules/**：项目规则文件
- **预留目录（备用适配）**
  - **.workbuddy/**、**.codex/**、**.cursor/** 等：为将来适配其他 AI harness 预留的配置目录，当前项目未使用；如后续启用，遵循与 `.trae/` 相同的结构规范
- **其他工具配置**
  - **.obsidian/**：Obsidian 配置文件，用于 MD 文档渲染和界面配置
- **通用适配原则**
  - Skill 文档与项目规则的核心内容（项目理念、处理流程、资料标准）设计为**可跨 harness 复用**，不绑定特定工具
  - 各 harness 目录仅存放该工具的适配入口与专属配置，不复制核心内容；同一份核心内容可在多个 harness 目录中共享引用

### 处理工具与模型目录

- **models/**：存放 Marker PDF 处理所需的模型文件
  - **layout/**：布局模型
- **tools/**：本地工具链目录
  - **llama_cpp/**：llama.cpp 工具链（含 CUDA 运行时 DLL），用于 GPU 加速推理
- **scripts/**：核心处理脚本目录
  - 包含 PDF 处理、图像分析、GPU 检查等脚本
- **venv/**：Python 虚拟环境目录，存放项目依赖

### 标准与项目文档目录

- **llm_standard/**：存放标准化处理的相关标准和指南：
  - **std_guide/**：存放标准化指导文件
    - **pdf_guide/**：存放 PDF 相关文档的处理标准，包括章节拆分和入口文档撰写指南
    - **参考文档**：[PDF 文档处理规则索引](../../../../llm_standard/std_guide/pdf_guide/index.md)
- **docs/**：项目文档目录
  - **images/**：项目图片资源（如公众号二维码）
  - **work_logs/**：工作日志目录，记录项目的工作进展与归档日志

### 源材料目录

- **pdf/**：PDF 文档处理目录
  - **input/**：存放输入的 PDF 文档
  - **output/**：存放处理后的 Markdown 文档和提取的图片
- **html/**：存放直接用于大模型分析的 HTML 和附件内容
- **source/**：存放 GitHub 处理所需的源代码下载

### 处理产物目录

- **llm_processed/**：存放 LLM 处理后的文档，按出版社/平台 → 期刊/账号 → 文章的层级组织
  - **参考文档**：[资源规范化处理](../04_resource_normalization/04_resource_normalization.md)
- **paper_skills/**：存放提取的技能知识，按照三种方式分类：
  - **by_journal/**：按期刊分类
  - **by_method/**：按方法分类
  - **by_topic/**：按主题分类
  - **参考文档**：[Paper Skill 创建指南](../06_paper_skill_creation/06_paper_skill_creation.md)

### 目录命名规则

为确保跨平台兼容性和工具可分析性，目录命名应遵循以下规则：

1. **空格处理**：使用下划线 (`_`) 替代空格
2. **特殊字符处理**：避免使用特殊字符，如 `&`、`@`、`#`、`$` 等，使用下划线替代
3. **长度限制**：目录名称应保持合理长度，避免过长
4. **一致性**：保持命名风格一致，使用小写字母和下划线
5. **可读性**：确保目录名称清晰易懂，反映其内容

**示例**：
- 错误：`Springer Nature/Nature Protocols`
- 正确：`Springer_Nature/Nature_Protocols`
- 错误：`Molecular & Cellular Proteomics`
- 正确：`Molecular_Cellular_Proteomics`

### 索引文件

每个分类目录下都包含索引文件，用于：
- 记录分类的定义和目的
- 列出所有子分类
- 建立技能文档与源文档的映射关系
- 跟踪更新记录

## 唯一标识符

- **学术文献**：使用DOI作为唯一标识符
- **技术说明书**：使用复合标识结构 `[项目/组织标识]-[方法/主题标识]-[文档类型]-[版本号]`

## 管理原则

1. **多维度分类**：同一篇文章的技能知识可以同时出现在多个分类中
2. **索引更新**：每次添加新文档后，及时更新相应的索引文件
3. **一致性**：保持技能文档的格式和结构一致
4. **可扩展性**：随着文档数量的增加，及时调整分类结构
5. **可追溯性**：确保每个技能文档都能追溯到原始源文档

## 实践指南

### 技能文档创建

1. 从处理后的Markdown文档中提取核心技能
2. 按照统一格式组织技能文档
3. 包含文档来源、技能摘要、详细说明等内容

### 分类归档

1. 根据文章的期刊、使用的方法和研究主题进行分类
2. 在每个分类目录下创建对应的技能文档
3. 更新相应的索引文件

### 索引维护

1. 定期检查和更新索引文件
2. 确保映射关系的准确性
3. 记录更新历史

通过这种系统化的资料管理方法，您可以构建一个结构化的技能知识体系，为后续的研究和应用提供有价值的参考。
