# 文件命名规范

## 概述

本指南提供 Paper2Skill 工具中统一的文件命名规范，综合了项目中各个模块的命名要求，确保文件命名的一致性和可读性。通过遵循这些规范，可以提高文件的可管理性和可检索性。

## 通用命名规范

### 基本原则

1. **一致性**：保持文件命名风格的一致性
2. **可读性**：确保文件名称清晰易懂，反映文件内容
3. **唯一性**：确保文件名称在其目录中是唯一的
4. **兼容性**：确保文件名称在不同操作系统中都能正常使用

### 通用规则

- **字母大小写**：使用小写字母
- **空格处理**：使用下划线 (`_`) 替代空格
- **特殊字符**：避免使用特殊字符，如 `&`、`@`、`#`、`$` 等，使用下划线替代
- **长度限制**：文件名称应保持合理长度，避免过长
- **扩展名**：使用适当的文件扩展名

## 特定文件命名规范

### 1. 技能文档命名

**规范**：`{核心技术术语}-{期刊全称}-{发表年份}.md`

**规则**：
- **核心技术术语**：选择文章中最具代表性、独特的专业术语或技术缩写
- **期刊全称**：使用期刊的完整名称，空格用连字符 (`-`) 替换
- **发表年份**：使用四位数字的年份

**示例**：
- `LiP_SRM-Nature_Biotechnology-2014.md`
- `LiP_MS_Protocol-Nature_Protocols-2017.md`
- `LiPAnalyzeR-Molecular_Cellular_Proteomics-2025.md`

**参考**：[Paper Skill 创建指南](../06_paper_skill_creation/06_paper_skill_creation.md)

### 2. 处理后文档命名

**规范**：`{唯一标识符}.md`

**规则**：
- **唯一标识符**：优先使用 DOI 后缀，无 DOI 时使用标准化的文章标题
- **格式**：保持简洁，避免使用特殊字符

**示例**：
- `nbt.2999.md`
- `10.1016_j.cell.2025.01.001.md`

### 3. 图片文件命名

**规范**：`figure_{序号}.{扩展名}`

**规则**：
- **figure**：固定前缀
- **序号**：使用阿拉伯数字，从1开始
- **扩展名**：使用图片的原始扩展名，如 jpeg、png、svg 等

**示例**：
- `figure_1.jpeg`
- `figure_2.png`

### 4. 脚本文件命名

**规范**：`{功能}_{版本}.py`

**规则**：
- **功能**：描述脚本的主要功能，使用小写字母和下划线
- **版本**：使用 vX.Y.Z 格式
- **扩展名**：使用 .py 扩展名

**示例**：
- `pdf_convert_v1.0.py`
- `skill_extract_v2.1.py`

### 5. 目录命名

**规范**：
- **出版社/平台目录**：使用标准化的出版社或平台名称，空格用下划线 (`_`) 替换
- **期刊/账号目录**：使用期刊或账号的名称，空格用下划线 (`_`) 替换
- **文章目录**：使用 DOI 后缀或自定义标识符

**示例**：
- 出版社目录：`Springer_Nature`、`Elsevier`
- 期刊目录：`Nature_Biotechnology`、`Molecular_Cellular_Proteomics`
- 文章目录：`nbt.2999`、`j.mcpro.2025.100934`

**参考**：[期刊论文唯一标识指南](../03_document_identification/03_01_pdf_document_identification/03_01_06_journal_identifier.md)

### 6. 技术说明书命名

**规范**：`{项目/组织标识}-{方法/主题标识}-{文档类型}-{版本号}`

**规则**：
- **项目/组织标识**：基于文档来源的组织或项目名称
- **方法/主题标识**：基于文档的核心方法或主题
- **文档类型**：基于文档的具体类型（如 Protocol、Guide、Manual 等）
- **版本号**：基于文档的版本信息

**示例**：
- `EUBOPEN-LiP-MS-Protocol-v1.0`

**参考**：[技术报告识别指南](../03_document_identification/03_01_pdf_document_identification/03_01_05_technical_report_identification.md)

## 命名一致性维护

### 检查与验证

- **定期检查**：定期检查文件命名是否符合规范
- **批量重命名**：对不符合规范的文件进行批量重命名
- **自动化验证**：使用脚本自动化验证文件命名规范

### 常见问题及解决方案

| 问题类型 | 可能原因 | 解决方案 |
|---------|---------|---------|
| 命名不一致 | 缺乏统一的命名规范 | 制定并遵循本指南的命名规范 |
| 特殊字符问题 | 使用了不兼容的特殊字符 | 替换为下划线或删除特殊字符 |
| 长度过长 | 文件名称过于冗长 | 简化文件名称，保留关键信息 |
| 重复命名 | 缺乏唯一性检查 | 确保文件名称在目录中唯一 |

## 最佳实践

1. **标准化**：使用统一的命名规范
2. **简洁性**：保持文件名称简洁明了
3. **描述性**：确保文件名称能够准确描述文件内容
4. **一致性**：在整个项目中保持命名风格的一致性
5. **前瞻性**：考虑文件名称的可扩展性和未来需求

通过遵循这些文件命名规范，可以提高项目的可管理性和可维护性，为文件的组织和检索提供便利。
