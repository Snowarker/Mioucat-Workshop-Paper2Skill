# Paper2Skill 工具用户指南

## 欢迎使用 Paper2Skill 工具

Paper2Skill 是一个基于大语言模型的多源信息抽取工具集，专注于从科研文献、专利、GitHub 仓库、网络文章、R 包和 Python 包中抽取关键信息，生成规范化的 Markdown 文档。整个项目基于 Wiki 知识库体系构建（详见下文[项目理念与工程化框架](#项目理念与工程化框架)），以真实材料的交叉引用为骨架，入库即构建知识网络并保留 ground truth。本指南将帮助您快速上手并充分利用该工具的各项功能。

## 项目理念与工程化框架

本技能文档集是资料整理的最终目标之一，但整个项目体系基于 Wiki 知识库模式构建：以真实材料的显式交叉引用为骨架，在资料入库时同步构建知识网络，并为每一份资料保留可验证的 ground truth（最原始版本）。本框架是全部技能文档的指导思想，所有分类文档均应在此框架下理解和执行。

### 核心哲学

#### 1. Wiki 知识库优先，而非 RAG 向量检索

本项目构建知识库的基本模式是 **Wiki 式显式链接**，而非传统 RAG（检索增强生成）的向量相似度隐式检索。两者的本质区别在于：

| 维度 | Wiki 知识库（本项目） | RAG 向量检索（非本项目模式） |
|------|----------------------|------------------------------|
| 知识组织方式 | 真实材料之间的显式交叉引用 | 向量空间中的隐式相似度 |
| 可追溯性 | 每个知识点直接链接到真实材料 | 检索结果依赖模型生成，存在幻觉风险 |
| 构建时机 | 资料入库时即完成关联 | 检索时动态计算 |
| 验证方式 | 沿链接逐级核查原始内容 | 依赖向量相似度打分 |
| 知识网络 | 长期积累、稳定可维护的网状结构 | 每次检索临时组装 |

本项目以真实材料的交叉引用作为知识库构建的基础，确保任何结论都能沿显式链接回溯到原始出处。

#### 2. 入库即构建知识网络

**优先在资料入库时构建知识库的网络，是本项目最理想、也是默认的工作状态。** 每份资料进入系统时，同步完成：

1. 识别其来源类型（论文、网页、GitHub、R 包、Python 包等）
2. 建立与其关联材料的交叉引用（引用了谁、被谁引用、属于哪个主题簇）
3. 登记到相应的索引文件中
4. 后续的 LLM 分析与 Skill 提取全部基于已建立的知识网络展开

避免"先堆材料、后补关系"的被动整理模式。

#### 3. Ground Truth 保留

每一份资料都必须保留其 **ground truth**——即最原始、未经处理的版本：

- **PDF 文档**：保留原始 PDF 文件
- **网页材料**：保留浏览器另存为的完整 HTML 文件
- **GitHub 仓库**：记录仓库地址与 commit 哈希
- **R 包**：记录包名、版本号与仓库来源
- **Python 包**：记录包名、版本号与仓库来源

所有处理产物（规范化 Markdown、LLM 分析结果、提取的 Skill 文档）均需通过相对路径链接回 ground truth，原始版本是验证一切处理结果的基准。

#### 4. 多源材料统一融合

本项目统一处理以下类型的技术材料，遵循同一套 Wiki 化入库流程：

- **论文类**：期刊论文、会议论文、预印本、书籍章节、技术报告、专利
- **网页类**：微信公众号文章、技术博客、官方文档网页
- **代码仓库类**：GitHub 仓库源代码
- **代码包类**：R 包（CRAN/Bioconductor 等）、Python 包（PyPI/conda-forge 等）

#### 5. Paper Skill 是目标，知识库是体系

Paper Skill（及各类材料的 Skill 文档）是整理的**最终产物**，用于沉淀可复用的结构化技能知识；但支撑它的不是孤立的文档堆，而是整个 **Wiki 知识库体系**。Skill 文档应被视为知识网络中的特殊节点——它既消费知识网络（从规范化材料中提取），也回馈知识网络（通过索引与交叉引用指向原始材料）。

### 工程化原则

#### 相对路径引用

所有文档之间的交叉引用**一律使用相对路径**，确保无论仓库被克隆、移动或部署到任何环境，链接都能定位到对应内容。

- 同一目录下：`03_04_r_package_identification.md`
- 跨目录向上：`../04_resource_normalization/04_resource_normalization.md`

禁止使用绝对路径（如 `D:\...`、`/home/...`）或仅依赖工具内置索引的引用方式。

#### 版本显式化

代码类材料（GitHub 仓库、R 包、Python 包）必须记录明确的版本信息：

- **R 包**：`包名_版本号`（如 `dplyr_1.1.4`），来源仓库（CRAN/Bioconductor）
- **Python 包**：`包名-版本号`（如 `pandas-2.2.2`），来源仓库（PyPI/conda-forge）
- **GitHub 仓库**：仓库地址 + 分支 + commit 哈希

版本信息随资料入库，作为知识网络节点的属性之一。

#### 结构化组织

按功能域划分目录，同类文档集中管理：`01_core_process/`（核心流程与环境设置）、`03_document_identification/`（文档来源识别，含 R 包、Python 包识别）、`05_data_management/`（资料管理与索引）等。

### 入库标准流程

每一份资料入库时，按以下标准流程执行：

1. **获取原始材料**：保存/下载最原始版本，作为 ground truth
2. **来源识别**：按[文档来源识别](03_document_identification/03_document_identification.md)确定材料类型
3. **规范化处理**：按[资源规范化处理](04_resource_normalization/04_resource_normalization.md)转为标准 Markdown
4. **建立交叉引用**：链接相关材料、登记索引，构建知识网络（入库即构建）
5. **LLM 分析**：基于规范化材料进行深度分析
6. **Skill 提取**：生成结构化技能文档，并链接回原始材料

## 核心功能

- **PDF 文档转换**：将 PDF 格式的论文和专利转换为可编辑的文本格式
- **HTML 网页处理**：处理本地保存的 HTML 网页文件，如微信公众号文章
- **GitHub 仓库处理**：克隆 GitHub 仓库并为大模型分析准备结构化内容
- **代码包处理**：识别与获取 R 包（CRAN/Bioconductor）和 Python 包（PyPI/conda-forge）材料，记录版本信息
- **网络文章处理**：爬取和处理微信公众号、小红书等网络文章
- **大语言模型处理**：利用先进的 LLM 技术深度分析和理解文档内容
- **Skill 信息提取**：从处理后的内容中提取结构化的技能知识
- **Wiki 知识库构建**：入库时建立真实材料之间的交叉引用与索引，形成可追溯的知识网络
- **Markdown 文档生成**：生成规范化、易读的 Markdown 文档
- **目录结构管理**：提供清晰的目录结构，便于内容组织和访问

## 技术要求

- **操作系统**：Windows 10/11 或 WSL2 (Ubuntu)
- **Python 版本**：3.10.x（推荐版本，如 3.10.11，仅用于PDF处理）
- **依赖项**：详见 `requirements.txt` 文件
- **硬件要求**：建议至少 8GB RAM，推荐 16GB 或更高
